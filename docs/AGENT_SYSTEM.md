# Agent workforce — implemented boundary

The API can seed one per-token Head Manager and ten distinct role identities: Android, Web, Game, UI/UX, Backend, Database, Security, QA, Research, and Documentation. Their role IDs, prompts, provider/model settings, specialties, temperature/context preferences, status, priority, memory toggle, bounded duration, and permission metadata persist in the database. Credentials are attached to owner-scoped provider connections, not agent rows.

`POST /api/v1/tasks/{id}/execute` performs real provider calls through the configured provider router. The Manager returns a JSON plan; the API accepts only 1–5 unique known worker identities, persists assignments, calls workers serially, stores reports, and requests final Manager synthesis. Parse/provider/tool errors mark the task failed; no fabricated answer is stored. Workers may request at most three deterministic safe tools per assignment when those exact tools are granted in that agent's `tool_permissions`; NOVA validates each request, persists results/messages/events, then asks the worker to produce its report from the actual results. The Manager's delegation plan cannot call tools. A single API request currently runs the whole operation; no queue process, scheduler, parallel delegation, lease, crash resume, cancellation, or automatic retry loop exists. Explicit user retry is bounded by `max_attempts`.

The only current tools are `math.calculate` (restricted arithmetic AST, not Python `eval`), `text.analyze` (bounded text counts), and `memory.search` (only the agent's own notes plus headquarters notes for the same owner). Permissions default empty. There is no shell, filesystem, browser, arbitrary network, external-action or destructive tool; therefore the current registry has no high-risk action to approve. New tools that can affect external systems must be separately reviewed and approval-gated before addition.

Agent memory is a small owner-scoped notes table, not vector search. With memory enabled, an agent receives up to six high-importance agent/headquarters notes as quoted context; project notes are stored but not yet attached to tasks. Agent-to-agent messages are persisted and owner-scoped.

Use `/api/v1/agents/seed` idempotently. Configure and test each provider connection, then edit each agent's exact provider and discovered model ID. Repeated identities remain independent even if provider/model values are shared. `docs/ARCHITECTURE.md` lists the deployment constraints; do not represent this API-triggered serial executor as a durable workflow service.
