# Agent workforce — implemented boundary

The API can seed one per-token Head Manager and ten distinct role identities: Android, Web, Game, UI/UX, Backend, Database, Security, QA, Research, and Documentation. Their role IDs, prompts, provider/model settings, specialties, temperature/context preferences, status, priority, memory toggle, bounded duration, and permission metadata persist in the database. Credentials are attached to owner-scoped provider connections, not agent rows.

`POST /api/v1/tasks/{id}/execute` performs real provider calls through the configured provider router. Alternatively, run `python -m nova_api.queue_worker`; it polls persisted owner-scoped tasks, waits for same-owner prerequisites, observes per-owner concurrency settings, and dispatches executions. The Manager returns a validated DAG of 1–5 unique known worker identities; ready independent assignments run concurrently up to configured concurrency, persist reports, and feed dependent worker context and final Manager synthesis. Parse/provider/tool errors remain failed; no fabricated answer is stored. Tasks and assignments maintain leases, heartbeat/checkpoint progress, and bounded attempts. Expired leases fail only unfinished assignments; an exact matching completed assignment (same key, title, instructions, and prerequisite keys) is reused on re-planning, while mismatches run fresh work. Ordinary failures use bounded exponential backoff. Workers may request at most three deterministic safe tools per assignment when those exact tools are granted in that agent's `tool_permissions`; NOVA validates each request, persists results/messages/events, then asks the worker to produce its report from actual results. The Manager's delegation plan cannot call tools. Owner cancellation and employee stop are cooperative between provider calls; an in-flight provider HTTP request is not interrupted. Multi-replica active-capacity arbitration and shared websocket event delivery remain deployment gaps.

The only current tools are `math.calculate` (restricted arithmetic AST, not Python `eval`), `text.analyze` (bounded text counts), and `memory.search` (only the agent's own notes plus headquarters notes for the same owner). Permissions default empty. There is no shell, filesystem, browser, arbitrary network, external-action or destructive tool; therefore the current registry has no high-risk action to approve. New tools that can affect external systems must be separately reviewed and approval-gated before addition.

Agent memory is a small owner-scoped notes table, not vector search. With memory enabled, an agent receives up to six high-importance agent/headquarters notes as quoted context; project notes are stored but not yet attached to tasks. Agent-to-agent messages are persisted and owner-scoped.

Use `/api/v1/agents/seed` idempotently. Configure and test each provider connection, then edit each agent's exact provider and discovered model ID. Repeated identities remain independent even if provider/model values are shared. Apply migration `0006_task_queue_leases.sql` after `0005_agent_chat.sql` for PostgreSQL deployments. `docker compose up --build` starts the API and polling worker. `docs/ARCHITECTURE.md` lists the remaining multi-replica deployment constraints.
