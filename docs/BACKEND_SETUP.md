# Backend setup

Python 3.11+, pinned packages in `backend/requirements.txt`. From repository root create a virtualenv, install requirements, copy `.env.example` to `.env`, set `NOVA_ADMIN_TOKEN`, then `set -a; . ./.env; set +a`, `cd backend`, and run `uvicorn nova_api.main:app --reload --host 0.0.0.0 --port 8000`. To accept provider keys from mobile, also set a persistent `NOVA_CREDENTIAL_ENCRYPTION_KEY` generated by `python -c 'from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())'`. Keep it in your secrets manager and back it up. Local default is SQLite; tables are created at application startup. Swagger/OpenAPI at `/docs`, schema at `/openapi.json`.

For Docker Compose, set `POSTGRES_PASSWORD`, `NOVA_ADMIN_TOKEN`, and (for mobile provider-key entry) `NOVA_CREDENTIAL_ENCRYPTION_KEY` in an untracked `.env`; run `docker compose up --build`. Set `NOVA_DATABASE_URL=postgresql+psycopg://...` for PostgreSQL. The SQL files under `database/migrations/` are baselines and have not been wired to a migration runner; in current code SQLAlchemy `create_all` initializes tables. Do not use this setup as production until Alembic/migration automation, TLS, shared rate limiting, backups, deployment secret management and health/observability are added.

Credentials: provider keys may come from backend environment or mobile setup. Mobile-entered Arena keys are Fernet-encrypted using `NOVA_CREDENTIAL_ENCRYPTION_KEY` before database storage; keep this key backed up because losing it makes stored secrets undecryptable. NOVA raw API keys are returned once and stored as SHA-256 digests. Client scopes: assistant `assistant:read`/`assistant:write`; provider setup `providers:read`/`providers:write`; tasks `tasks:read`/`tasks:write`; agents `agents:read`/`agents:write`; events `events:read`. Rate limit is in-process 120 requests/IP/minute and is not a distributed control.
