# Provider connections, free access, and quotas

For the strict client-secret boundary, upstream provider API keys must be injected into the NOVA backend runtime secret environment (or configured in the external gateway); ordinary NOVA app clients cannot submit them through the settings APIs. The Android app can store only a restricted external-gateway access token, sent to the configured HTTPS NOVA backend and encrypted at rest using `NOVA_CREDENTIAL_ENCRYPTION_KEY`. It is never sent directly to an upstream AI provider. Do not put the OG administrator token in the app. Existing legacy encrypted provider records remain backend-side and are never returned to clients.

NOVA discovers model IDs from each provider account. Use the returned exact ID; model names and free availability can change. There is no universal free tier, no fixed 11-model requirement, and no unlimited quota promise.

| Provider | Verified API endpoint / setup | Free-tier and quota note |
| --- | --- | --- |
| Arena | Configured OpenAI-compatible base URL; backend runtime key required. | No free quota claim made here. |
| OpenAI | Native OpenAI API adapter; configure `NOVA_PROVIDER=openai` and inject its key as `NOVA_PROVIDER_API_KEY` into backend runtime. | Account/model billing and limits apply; NOVA makes no free-quota claim. |
| Anthropic / Claude | Native Anthropic Messages adapter; configure `NOVA_PROVIDER=anthropic` and inject its key as `NOVA_PROVIDER_API_KEY` into backend runtime. | Account/model billing and limits apply; NOVA makes no free-quota claim. |
| Groq | `https://api.groq.com/openai/v1`; key required. Current rate limits are account/model-specific; check the provider console. | NOVA does not claim a universal free quota. |
| Gemini API | Native `https://generativelanguage.googleapis.com/v1beta` model discovery and `generateContent`; API key is sent in `x-goog-api-key` from backend runtime. | Google documents a free usage tier for eligible projects, but RPM/TPM/RPD vary by model/account and are not guaranteed. View active limits in AI Studio. NOVA's adapter is mock-tested, not live-tested. |
| OpenRouter | `https://openrouter.ai/api/v1`; API key required; model discovery is account-dependent. | Free-model eligibility and limits depend on the current catalog/account. NOVA does not assume a free model. |

NOVA can enforce the per-connection daily request ceiling and owner-level daily request budget configured in the API. Provider-enforced rate limits, billing limits, and account quota responses remain authoritative. Fallback is finite and only tries configured compatible connections; 402 payment-required errors stop rather than spend elsewhere. Token counts are displayed only when a provider returns usage metadata; dollar cost is not estimated without reliable pricing metadata.

## In-app setup and gateway deployment

In Android, open **Settings → Configure multi-provider router**, choose `openai_compatible` (LiteLLM, Bifrost, New API, Cloudflare AI Gateway, or another OpenAI-compatible gateway), `anthropic_compatible`, or the legacy `claude_gateway`, enter its HTTPS `/v1` base URL and a restricted gateway access token, then use **Save and test**. The backend operator must first set `NOVA_GATEWAY_ALLOWED_HOSTS` to exact DNS hostnames, comma-separated, without wildcards. NOVA rejects non-HTTPS URLs, unlisted hosts, credentials embedded in URLs, query/fragment strings, non-default ports, and paths other than `/v1`. The app will not accept upstream provider keys; inject those into backend runtime secrets or configure them in the external gateway. After model discovery, select the exact model ID for an agent. Saved gateway connections can be retested or disconnected. Each owner can currently save one connection per gateway type.

The setup test performs model listing only. It does not make a completion request, promise that a model is callable, verify billing, or imply free inference. A failed test is persisted as an error and should not be treated as connected. Never use a gateway project's sample development tokens in deployment; use unique restricted tokens, protect its admin/config surface, terminate TLS, and configure upstream providers there.

NOVA also exposes an owner-authenticated text-only compatibility facade at `/v1/models`, `/v1/chat/completions`, and `/v1/messages`. Use a scoped NOVA application key (`assistant:read`/`assistant:write`), never `NOVA_ADMIN_TOKEN`. It supports basic user/assistant/system text, model selection, completion token caps, SSE streaming for supported OpenAI-compatible and Anthropic Messages upstreams, usage when upstream reports it, request IDs, and explicit fallback headers. Unsupported content blocks are rejected. A broken stream is cancelled/closed and must be retried as a new generation; it cannot resume. Native Gemini/Cloudflare streaming, tool use, images, audio and full protocol parity are unsupported. Claude Desktop and real providers have not been live-tested.
